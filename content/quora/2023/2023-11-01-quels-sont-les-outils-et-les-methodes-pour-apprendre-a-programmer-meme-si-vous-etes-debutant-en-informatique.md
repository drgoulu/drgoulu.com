*Réponse publiée [sur Quora](https://fr.quora.com/Quels-sont-les-outils-et-les-m%C3%A9thodes-pour-apprendre-%C3%A0-programmer-m%C3%AAme-si-vous-%C3%AAtes-d%C3%A9butant-en-informatique/answer/Dr-Goulu)*

1. Suivre les instructions et le tutoriel du langage choisi. Par exemple pour [Python c est là](https://docs.python.org/3/tutorial/index.html).
2. Prendre tout de suite les bonnes habitudes en installant Gît et un bon IDE comme VS Code.
3. Choisir un projet raisonnable pour commencer. Aller sur GitHub et constater qu'il existe plusieurs projets similaires. Les installer, compiler, tester et voir comment leur code est écrit, documenté etc.
4. "Forker" le projet qui vous plaît le plus dans GitHub et essayer de corriger des bugs ou de faire de petites modifications. Pushez dans votre fork et faites un pull request pour que le programmeur principale accepte (ou pas…) vos améliorations.

Ceci n'est absolument pas l'approche que j'ai suivie il y a 45 ans, parce que TOUT a changé.

1. Si vous démarrez un petit projet perso dans votre coin, vous allez être déçu et découragé en constatant qu'il existe plein de logiciels similaires bien mieux foutus.
2. Vous allez "réinventer la roue" une fois de plus alors que la programmation moderne reutilse un max de code déjà existant.
3. Vous allez travailler tout seul alors que la programmation est désormais un travail collectif grandement automatisé par des outils comme Gît / GitHub qu'il est indispensable de maîtriser aussi.
4. Configurer un projet pour qu'il s'installe avec ses dépendances et utilise les outils susmentionnés est très pénible et frustrant.

Donc mon conseil après une carrière de développement bien remplie est : ne commencez jamais un projet de zéro. Partez toujours d'un projet existant. Il existe même des "project template" ou des "project generator" qui vous les fabriquent.

Et si ça n'existe pas dans le langage que vous choisissez (Visual Basic, Cobol, Fortran…), changez de langage.
